# 패스워드 가디언 시각 제작 기준

## 1. 참고 자료와 적용 상태

2026-10-12 대화에 첨부된 ‘배경 에셋 / 기체 에셋 / 탄환 에셋 / 효과·UI 에셋’ 보드를 주된 시각 참고 자료로 사용한다. 보드의 금속 질감, 청록 조명, 기체별 색과 실루엣, 금고 공간의 단계별 변화를 제작 기준에 반영한다.

첨부 보드는 예시 시안이며 독립된 게임용 이미지 묶음이 아니다. 화면에 적힌 1920×1080·128×128 등의 수치는 개별 에셋의 목표 출력 규격으로 해석한다. 보드를 잘라 확대한 이미지를 최종 에셋으로 간주하지 않는다. 첨부 원본은 현재 프로젝트 파일로 저장되어 있지 않으며, 이 문서에 관찰한 내용을 정리했다.

기존 Kenney 팩 5개는 확보 상태를 유지한다. Space Shooter 조합은 기능 구현과 밸런스 검증용 임시 에셋, Simple Space·Pixel Shmup은 대안 스타일로 분류한다. 최종 시각 목표는 아래의 상세한 금속·SF 화풍이다. 해당 화풍의 완성 에셋은 아직 제작·확보하지 않았다.

## 2. 공통 미술 방향

- 소재: 짙은 금속 장갑, 선명한 패널 경계, 작은 기계 부품과 제한적인 발광.
- 기본 색: 검정·짙은 남색 바탕, 청록 조명. 적의 주황·보라·붉은색을 역할별로 구분한다.
- 시점: 움직이는 기체는 일관된 2D 탑다운 시점으로 제작한다. 금속 명암을 넣더라도 방향·실루엣이 명확해야 한다.
- 배경 시점: 시작·결과는 참고 이미지처럼 공간의 깊이를 표현할 수 있다. 전투 배경은 위에서 내려다보는 바닥·설비 중심으로 정리하여 기체의 이동 평면과 어긋나지 않게 한다.
- 문양: 자물쇠는 보호, 연결 고리는 유출 계정의 연쇄 위험을 표현한다. 작게 표시해도 읽히도록 단순화한다.
- 밝기: 밝은 탄환이 가장 먼저 보이고, 기체, 배경 장식 순으로 시선이 가도록 한다. 배경 코어·경고등의 발광은 전투용 버전에서 낮춘다.

## 3. 배경 5장

각 배경은 1920×1080, 16:9, 불투명 PNG로 개별 제작한다. 글자·버튼·랭킹은 이미지에 넣지 않고 Arcade UI로 표시한다.

| 에셋 ID·목표 파일 | 참고 이미지에서 반영할 요소 | 실제 사용 시 조정 |
|---|---|---|
| `bg_title` / `bg_title.png` | 자물쇠가 있는 대형 금고 문, 입구 통로, 양쪽 청록 조명 | 제목·시작 안내와 TOP 10이 놓일 영역의 장식 밀도 낮추기 |
| `bg_stage_1` / `bg_stage_1.png` | 금고 외곽의 어두운 복도·바닥 회로, 청록빛 구조물 | 중앙 이동 영역을 넓고 단순하게 확보, 원근 표현 완화 |
| `bg_stage_2` / `bg_stage_2.png` | 교차하는 데이터 통로, 연결망, 가장자리 붉은 경고 장치 | 경고 장치를 외곽에 배치하고 붉은 열쇠 탄환과 구별 |
| `bg_stage_3` / `bg_stage_3.png` | 금고 중심부의 원형 코어와 동심원 기계 구조 | 코어를 어둡게 처리하고 보스·탄막의 윤곽 확보 |
| `bg_result` / `bg_result.png` | 안정된 내부 공간, 청록색 잠금 홀로그램, 원형 받침대 | 총점·선택 결과·학습 메시지·랭킹을 위한 여백 확보 |

기존 별 배경 타일과 선으로 그린 금고 시안은 배치 검토에 사용한다. 최종 배경 5장을 확보한 것으로 집계하지 않는다.

## 4. 기체 5종

| 에셋 ID·목표 파일 | 외형·색상 기준 | 목표 출력 |
|---|---|---|
| `player` / `player.png` | 흰색·회색 장갑, 청록 발광, 방패 같은 좌우 날개, 중앙 자물쇠, 아래쪽 추진광 | 투명 RGBA PNG 128×128 1장 |
| `guess_bot` / `guess_bot.png` | 길쭉하고 단순한 회색 동체, 주황색 포구·발광, 좁은 좌우 장갑 | 투명 RGBA PNG 128×128 1장 |
| `dictionary_drone` / `dictionary_drone.png` | 넓은 부채꼴 날개와 여러 포구, 어두운 장갑, 보라색 발광 | 투명 RGBA PNG 128×128 1장 |
| `leaked_swarm` / `leaked_swarm.png` | 세 갈래 삼각형 실루엣, 주황색 장갑 끝부분, 중앙 연결 고리 문양 | 투명 RGBA PNG 128×128 1장, 군집에 재사용 |
| `intruder` / `intruder.png` | 넓고 날카로운 검은 장갑, 붉은 경계광, 중앙의 큰 붉은 원형 코어 | 투명 RGBA PNG 512×512 1장 |

작업 원본은 출력보다 크게 제작할 수 있으나 최종 크기에서 외곽선·문양이 읽히는지 확인한다. 기체 전체와 추진광이 잘리지 않도록 여백을 두고, 불꽃·외부 발광은 충돌 영역에서 제외한다. 투명도는 실제 알파 채널로 제공하며 검은 배경이나 체크무늬를 구워 넣지 않는다.

생성형 AI로 제작할 때의 기체별 프롬프트, 고르기 전 점검표, 후처리·출처 기록 절차는 [AI_IMAGE_PROMPTS.md](AI_IMAGE_PROMPTS.md)에 정리했다. 게임에 넣는 파일은 위의 정사각형 규격 대신 기체 경계에 맞춰 잘라낸 PNG를 쓴다. 게임이 이미지 폭을 기준으로 표시 크기를 맞추므로, 여백이 있으면 화면에서 기체가 작아진다.

## 5. 탄환·효과·UI

| 에셋 ID | 형태·색 | 목표 출력 |
|---|---|---|
| `bullet_player` | 청록색 자물쇠. 보호를 상징 | 투명 PNG 32×32 1장 |
| `bullet_guess` | 주황색 원 안의 `?`. 반복 추측 봇의 비밀번호 추측 | 투명 PNG 32×32 1장 |
| `bullet_dict` | 보라색 펼친 사전(`A｜가`). 사전 공격 드론 | 투명 PNG 32×32 1장 |
| `bullet_leak` | 붉은 열쇠. 유출 계정 군단의 유출된 로그인 정보 | 투명 PNG 32×32 1장 |
| `shield_effect` | 얇은 청록색 보호막 고리 | 투명 PNG 64×64 1장 또는 Arcade 도형 |
| `icon_health` | 붉은 하트 | 투명 PNG 64×64 1장 |
| `icon_shield` | 파란 방패 | 투명 PNG 64×64 1장 |
| `icon_skill` | 노란 번개 | 투명 PNG 64×64 1장 |

정적 래스터 출력은 총 18장(배경 5 + 기체 5 + 탄환 4 + 효과·아이콘 4)을 기준으로 한다. 보호막 고리를 코드로 구현하면 이미지 파일은 17장이다. 탄환은 공격의 의미가 보이도록 아이콘으로 표현하며, 보스는 세 가지 적 탄환을 섞어 쏜다. 프로토타입은 탄환 4종을 `assets.py`에서 코드로 그린다. 글자를 넣은 탄환(예: `1234`)은 탄막이 겹칠 때 읽기 어렵고 충돌 범위와 모양이 크게 어긋나 쓰지 않는다. 보호막은 실제 표시 크기에 맞춰 선명도를 확인하며, 큰 반경에는 도형 렌더링을 우선 고려한다. 추가 애니메이션은 후순위다.

## 6. 제작·선정 순서와 확인 기준

1. 참고 방향에 맞는 플레이어 1종, 일반 적 1종, 1단계 배경을 먼저 준비하여 색·질감·시점을 비교한다.
2. 1920×1080 화면에 실제 플레이 크기로 배치하고 탄환·체력·문양 가독성을 확인한다. 포스터처럼 확대해서 본 인상만으로 결정하지 않는다.
3. 대표 스타일을 맞춘 뒤 나머지 적·보스·배경·UI를 제작 또는 확보한다. 상세 원화 제작 일정은 기존 팩 활용 일정과 별도로 산정한다.
4. 밝은 배경 장식과 적 탄환을 혼동하지 않는지, 흑백에서도 기체 모양이 구분되는지 확인한다.
5. 파일별 알파 채널, 크기, 중심점, 충돌 도형, 출처·편집 내역을 점검하고 `ASSET_MANIFEST.md`에 등록한다.

최종 후보 판단에서는 참고 보드와의 질감·구도 일치뿐 아니라 실제 탄막 회피의 가독성을 함께 평가한다. 기존 다운로드 자료에 기록한 CC0 조건은 해당 Kenney 파일에만 적용되며, 참고 보드와 향후 제작물의 출처는 별도로 기록한다.
